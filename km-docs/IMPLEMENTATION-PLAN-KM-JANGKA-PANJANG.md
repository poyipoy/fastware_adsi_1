### Aturan eksekusi database

- Tidak ada tabel/kolom baru untuk bulk approval, popular analytics, atau health command. Ketiganya wajib memakai schema hasil fase sebelumnya.
- Sebelum migration, audit `SHOW INDEX FROM km_pengajuans`, engine tabel, dan keberadaan kolom. Bila index dengan semantics sama sudah ada, hentikan dengan pesan eksplisit; jangan membuat index duplikat atau mengganti namanya diam-diam.
- Migration harus additive dan reversible. Tidak ada backfill, delete, truncate, perubahan status, atau rekalkulasi counter pada fase ini.
- Uji `migrate → rollback batch → migrate` hanya setelah executor membuktikan `APP_ENV=testing` dan nama database berakhiran `_testing`. Jangan menjalankan rollback otomatis pada database non-testing.
- Full-text ini khusus MySQL dan metadata. Jangan menambahkan conditional SQLite fallback ke production code; feature test search dijalankan pada MySQL testing agar perilaku sama dengan production.

## Rollback Plan

- **Bulk approval:** hentikan akses UI dan revert route/controller ke release sebelumnya. Karena tidak ada schema baru, rollback bersifat code-only. Event yang sudah sah harus tetap append-only; jangan menghapus event atau mengembalikan status secara massal. Koreksi bisnis, bila diperlukan, dibuat sebagai event kompensasi setelah otorisasi terpisah.
- **FULLTEXT:** deploy lebih dulu kode search dari fase Jangka Menengah yang tidak memanggil named FULLTEXT index, lalu drop index melalui `down()`/migration kompensasi terkontrol. Jangan rollback migration saat application release aktif masih memakai `whereFullText`. Rollback tidak mengubah metadata dokumen.
- **Dashboard/export populer:** hapus link navigasi dan revert tiga route/controller/view/export. Karena fitur read-only dan tanpa schema, tidak ada data yang perlu dihapus; file hasil download yang sudah berada di perangkat user tidak dapat ditarik kembali.
- **Refactor/controller:** route legacy dipertahankan sehingga application dapat dikembalikan ke release sebelumnya tanpa migrasi data. Revert bundle/view/service/controller sebagai satu unit; jalankan route-list dan view-cache sebelum membuka traffic kembali.
- **`km:health`:** command dapat direvert secara code-only. Jangan “memperbaiki” hasil FAIL dengan menulis schema dari command; perbaikan schema selalu melalui migration terpisah.
- **Production database:** pola rollback utama adalah roll-forward application fix. Menjalankan migration `down()` di production memerlukan backup terverifikasi, maintenance window, dan pemeriksaan bahwa tidak ada application node yang masih bergantung pada index. Kolom/route legacy tetap dipertahankan minimal satu release.
